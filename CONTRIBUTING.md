# Конвенции команды

Свод правил по проекту. В скобках у правил указаны номера критерия оценки в чек-листе.

## 1. Стек и базовые требования

- iOS **17.0+**, **SwiftUI**, архитектура **MVVM**.
- Только **Swift Concurrency**. GCD и completion-хендлеры запрещены. *(Критерий №7)*
- Проект всегда собирается без ошибок и критичных warning'ов. *(Критерий №4)*

## 2. Пример структуры проекта

```
iOS-FakeNFT/
├── App/                    # точка входа: App, ContentView, TabBarView
├── Resources/              # Assets.xcassets, Localizable.xcstrings, шрифты
├── DesignSystem/           # цвета, шрифты, стили кнопок
├── Foundation/             # сетевой клиент, форматтеры, утилиты
│   └── NetworkClient/
├── Common/                 # компоненты, переиспользуемые между эпиками
│   ├── Atoms/              # мелкие кубики: рейтинг, аватар, картинка с сердцем, кнопка корзины
│   ├── Cells/              # общие ячейки (grid-ячейка NFT)
│   ├── Controls/           # кнопки, текстовые поля, сортировка
│   ├── State/              # состояния экрана: загрузка, ошибка, пусто, алерт
│   └── WebView/            # WebViewScreen
├── Models/                 # общие модели данных (Sendable)
├── Services/               # actor-сервисы для работы с сетью
│   └── Requests/           # описания запросов
└── Features/               # эпики, по одному на каждый
    ├── Catalog/
    ├── Cart/
    ├── Profile/
    └── Statistics/
```

Внутри каждого эпика (`Features/<Epic>/`):

```
Catalog/
├── Views/          # экраны эпика
├── ViewModels/     # @Observable + @MainActor
├── Models/         # модели, специфичные для эпика (если есть)
└── Components/     # ячейки только этого эпика
```

Правило размещения: компонент нужен двум или более эпикам - размещаем в `Common/`. Если компонент нужен одному экрану - в `Features/<Epic>/Components/`.

## 3. Архитектура (MVVM) *(Критерий №5)*

- **View** — только отображение и передача действий пользователя. Никакой бизнес-логики.
- **ViewModel** — `@Observable` + `@MainActor`. `ObservableObject` + `@Published` **не используем** и не смешиваем реализации.
- Модификаторы по назначению: `@State` — локальное состояние и владение VM, `@Binding` — связь между View, `@Environment` — внедрение зависимостей (`ServicesAssembly`).
- Один экран = одна ViewModel (или обоснованно общая внутри эпика).
- Данные между экранами передаем через ViewModel/сервис, а не через общий компонент.
- Навигация — через общий `Router` (из `Common/`) на каждую вкладку: `NavigationStack(path:)` + `Route`-enum эпика. Инлайновые `NavigationLink` не смешиваем с роутером.
- Роутер не допускает повторного открытия того же экрана при быстрых повторных нажатиях (защита от двойного `push`). *(Критерий №3 🍏)*

## 4. Сетевой слой *(Критерий №6, №7)*

- Сервисы эпиков — `actor`.
- Сетевые модели — `Sendable`.
- Запросы через `async/await`. Общий `NetworkClient` не меняем, сервисы пишем по образцу `NftServiceImpl`.
- Реализуем нужные типы запросов: GET / POST / PUT / DELETE.
- Обработка ошибок (нет сети / невалидные данные) — через общий алерт с Retry.

## 5. Многопоточность *(Критерий №7)*

- UI обновляется **только** на `@MainActor`.
- Где уместно — `async let`, `withTaskGroup`.
- Избегаем race conditions и deadlock'ов.

## 6. Верстка и UI *(Критерий №1, №3)*

- Только SwiftUI. UIKit запрещен, **кроме** `WKWebView` через `UIViewRepresentable`.
- Переиспользуемые компоненты берем из `Common/`, **не дублируем**.
- Загрузка — `ProgressView`. Пустые состояния — общий `EmptyStateView`.
- Отступы по макету, стремимся к pixel-perfect.

## 7. Дизайн-система *(Критерий №3, Доп. критерий №3)*

- Цвета **только из палитры**. Хардкод цветов запрещен.
- Шрифты — из общего `extension Font`.
- Иконки и картинки — из `Assets`.

## 8. Локализация *(Доп. критерий №2)*

- Весь текст — через **String Catalog** (ENG основной,RU - дополнительый, арабский - отдельной задачей в конце).
- Хардкод-строк нет.
- Ключи в формате `Экран.Элемент` (например: `Catalog.title`).

## 9. Хранение данных *(Критерий №8)*

- Локальные настройки (сортировка и т.п.) — через `@AppStorage` / `UserDefaults`.

## 10. Чистота кода *(Критерий №9)*

- **SwiftLint обязателен**, перед PR — 0 ошибок линтера.
- CamelCase, описательные имена, короткие функции (одна ответственность).
- SOLID / KISS / DRY / YAGNI, минимум дублирования.
- **Отсутствие Force operations** (force unwrap / try / cast).
- Нет неиспользуемого и закомментированного кода.
- Числа и даты - только через общие форматтеры.

## 11. Git

### Ветки

**Подготовительные задачи:**
- Ветка `prep/<описание>` от `develop` (например: `prep/swiftlint`, `prep/design-tokens`).
- Вливается в `develop` пул-реквестом, апрув не требуется.

**Эпики:**
1. От `develop` ответвляем ветку эпика: `epic/<name>` (напр. `epic/catalog`).
2. От `epic/<name>` ответвляем части по декомпозиции: `<name>/<часть>` (напр. `catalog/collections-list`).
3. Каждую часть вливаем в `epic/<name>`.
4. Когда **все части** влиты в `epic/<name>` — ветку эпика пул-реквестом вливаем в `develop`.

```
develop
 └── epic/catalog
      ├── catalog/collections-list     → merge в epic/catalog
      ├── catalog/collection-screen    → merge в epic/catalog
      └── catalog/nft-actions          → merge в epic/catalog
 (все части влиты) → epic/catalog → PR в develop
```

### Коммиты — Conventional Commits

Формат: `<type>(<scope>): <описание>`

| type | когда |
|---|---|
| `feat` | новая функциональность |
| `fix` | исправление бага |
| `refactor` | рефакторинг без смены поведения |
| `style` | форматирование, отступы (не UI) |
| `chore` | конфиги, зависимости, рутина |
| `docs` | документация |
| `test` | тесты |

- **scope** — эпик или компонент (`catalog`, `cart`, `common`), опционально.
- Описание — в повелительном наклонении, с маленькой буквы, без точки в конце.

Примеры:

```
feat(catalog): add collections list screen
fix(cart): correct total price calculation
refactor(common): extract NftGridCell from catalog
chore(lint): add swiftlint config
```

### Pull Request *(Критерий №10)*

- Описание PR: что и зачем, ссылка на таску. Указавать архитектуру (MVVM) и верстку (SwiftUI) только на пул реквестах своего эпика.
- Кросс-ревью опционально. Но все комментарии оставленные в пул реквесте должны быть решены - `resolved`
- В чужие таски не коммитим.
